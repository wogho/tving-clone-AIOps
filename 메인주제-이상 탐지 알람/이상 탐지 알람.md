# TVING AIOps - CloudWatch Anomaly Detection & Slack 알람 시스템

## 1. 개요 (Overview)

본 문서는 **TVING 클론 서비스(ECS Fargate)**의 운영 안정성을 위해 구축된 **머신러닝(ML) 기반 이상 탐지(Anomaly Detection) 및 슬랙(Slack) 실시간 경보 파이프라인**의 아키텍처와 설정 내역을 기록합니다.

* **목적**: 정적 임계값(Static Threshold)의 한계를 극복하고, AWS ML 기반의 동적 예측 밴드를 통해 CPU/메모리 이상 징후를 감지하여 슬랙으로 1초 만에 실시간 전파
* **대상 서비스**: `tving-cluster` / `tving-backend-service` (ECS Fargate)
* **리전**: AWS 서울 리전 (`ap-northeast-2`)

## 3. 구축 리소스 명세 (Resource Specifications)

### 3.1 Amazon SNS Topic

* **Topic Name**: `tving-aiops-anomaly-alarm`
* **Topic ARN**: `arn:aws:sns:ap-northeast-2:761018884888:tving-aiops-anomaly-alarm`
* **구독(Subscription)**:
  * `tving-aiops-slack-notifier` (AWS Lambda)

---

### 3.2 CloudWatch Anomaly Detection Alarms

| 알람 이름 | 대상 메트릭 | 조건 식 (Threshold Math) | 평가 주기 | 연동 Action |
| :--- | :--- | :--- | :---: | :--- |
| **`tving-ecs-cpu-anomaly-alarm`** | `AWS/ECS` `CPUUtilization` | `ANOMALY_DETECTION_BAND(m1, 2)` (상한선 초과) | 60초 (1회) | `tving-aiops-anomaly-alarm` (SNS) |
| **`tving-ecs-memory-anomaly-alarm`** | `AWS/ECS` `MemoryUtilization` | `ANOMALY_DETECTION_BAND(m2, 2)` (상한선 초과) | 60초 (1회) | `tving-aiops-anomaly-alarm` (SNS) |

---

### 3.3 Slack Notifier Lambda 함수

* **함수명**: `tving-aiops-slack-notifier`
* **런타임**: Python 3.12
* **실행 역할**: `arn:aws:iam::761018884888:role/aiops-agent-tools-role`
* **환경 변수**:
  * `SLACK_WEBHOOK_URL`: `https://hooks.slack.com/services/T01V1UNJP7T/...`
* **핵심 로직**:
  * SNS 메시지에서 `AlarmName`, `NewStateValue`, `NewStateReason`, `StateChangeTime` 추출
  * 상태값(`ALARM`, `OK`)에 따라 TVING 브랜드 컬러 및 경보 이모지 적용
  * 슬랙 Block Kit 규격으로 구조화된 알림 카드 발송

## 4. 장애 주입 및 테스트 방법 (Fault Injection)

AIOps 이상 탐지 및 슬랙 알림을 검증하기 위해 백엔드에 테스트용 엔드포인트가 구성되어 있습니다.

### 4.1 백엔드 장애 주입 API

* **CPU 부하 발생**: `POST /ops/cpu-load?duration=10`
  * 인위적인 CPU 계산 루프를 실행하여 Fargate CPU 사용량을 급증시키고 `tving-ecs-cpu-anomaly-alarm`을 트리거합니다.
* **응답 지연 발생**: `POST /ops/delay?seconds=5`
  * ALB 지연시간(TargetResponseTime)을 증가시킵니다.
* **DB 에러 발생**: `POST /ops/db-error`
  * 비정상 SQL 쿼리를 실행하여 CloudWatch Logs에 500 에러를 기록합니다.

### 4.2 SNS ➔ Lambda ➔ 슬랙 수동 발송 테스트 명령어

```bash
aws sns publish \
  --topic-arn "arn:aws:sns:ap-northeast-2:761018884888:tving-aiops-anomaly-alarm" \
  --message '{"AlarmName":"tving-ecs-cpu-anomaly-alarm","NewStateValue":"ALARM","NewStateReason":"Threshold Crossed: CPUUtilization metric was greater than upper threshold (ML Anomaly Detection Band exceeded).","StateChangeTime":"2026-08-25T14:17:00Z"}' \
  --region ap-northeast-2
```

## 6. 기대 효과 및 차별점

1. **오탐(False Positive) 방지**: 정적 임계값과 달리 트래픽이 적은 새벽 시간대의 비정상 부하와 피크 시간대의 정상 부하를 머신러닝이 스스로 구분
2. **실시간 SRE 관제 가시성**: 이메일 대비 접근성이 높은 슬랙 채널을 통해 팀원 전체가 장애 상황을 즉시 인지
3. **Bedrock AIOps 엔진 연계 확장성**: 슬랙 알림을 시작점으로 Bedrock Agent가 에러 로그 분석(RCA) 및 운영 매뉴얼 RAG 조회를 수행하도록 자연스러운 파이프라인 구축
